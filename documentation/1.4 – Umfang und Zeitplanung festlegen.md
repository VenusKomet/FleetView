## 2.3 Entwicklungsprozess
Um das Projekt strukturiert und geplant durchzuführen, ist es notwendig ein für dieses Projekt angemessenes Vorgehensmodell zu wählen. Da die Anforderungen des Kunden sehr spezifisch vorliegen und ein fester, recht kurzer Zeitraum von 80h wenig Zeit für Anforderungsänderungen lassen, fiel die Entscheidung für das übergeordnete Projekt  auf das Wasserfallmodell. So war es möglich, das Projekt in konkrete und festgelegte Projektphasen einzuteilen (siehe Kapitel 2.1 Projektphasen) und diese nacheinander durchzuführen und abzuschließen, ohne in vorherige Phasen zurückzuspringen.

Für die Implementierungsphase wurden die verschiedenen Anforderungen in User Stories aufgeteilt. Diese wurden nacheinander abgearbeitet, indem das Backend, die Datenbank, das Frontend und Tests geschrieben und erstellt wurden. Hierfür wurde die User Storie dem Jeweiligen Projektmitglied zugewiesen und von diesem abgearbeitet. Während der Implementierung haben alle Projektmitglieder an einem Weekly Teilgenommen, wo aktuelle Blockaden und weitere Themen besprochen wurden.

Für die Versionsverwaltung wird Git nach dem Gitflow-Workflow verwendet. Dabei werden den verschiedenen Branches unterschiedliche Rollen zugewiesen. In diesem Projekt enthält der Main Branch alle veröffentlichten Features und umfasst somit das Produktivsystem. Für jede User Story wird ein eigener Branch angelegt. Um verschiedene Branches zusammenzuführen, muss ein Pull Request gestellt werden. Dieser muss von einem anderen Entwickler abgenommen werden. Dadurch werden die Codequallität und die Einhaltung der [FIRMA] Software Standards sichergestellt.
